## 输入摘要

PR #1426 的 Linux `Test cosh-ng` 在 Clippy 阶段失败。Rust 1.97 的
`clippy::useless_borrows_in_formatting` 检出 `cosh-core` 中传给 `format!`
的冗余引用；由于 CI 使用 `-D warnings`，warning 被提升为 error，后续
`cargo test --workspace` 未执行。

## 证据

- CI 报错位置为 `crates/cosh-core/src/core.rs:811`：
  `format!("{}-bypass", &tc.id)`。
- CI 建议删除冗余的 `&`，改为 `format!("{}-bypass", tc.id)`。
- 当前本机 Clippy 1.91 不包含该 lint，解释了本地门禁通过而 CI 失败。
- 该行自原始提交引入后一直存在，在最初的 #1426 两文件 diff 中没有变化。
- 用户已明确要求在 PR #1426 中捎带修复，不再维持此前只允许
  `platform` 和 `cli` 两个文件的范围限制。

## 影响范围

- `cosh-core` sandbox bypass 的 tool-use id 字符串构造。
- 所有在 Rust 1.97 stable 上运行 cosh-ng all-targets Clippy 的 PR。
- 不涉及运行时输出、所有权、公共 API、协议、依赖或 lockfile。

## 分诊判断

这是可稳定复现的单行 lint 基线问题。修复不会改变生成字符串或 move/borrow
语义，复杂度和不确定性均为 low，进入 `trivial/`，以独立原子 commit 加入
现有 PR #1426。

## 推荐路径

- 保留 GitHub Actions Rust 1.97 失败作为 RED 证据。
- 删除 `format!` 参数上的冗余 `&`，不做相邻重构。
- 新增独立 `[core]` commit，保持 #1361 的 svc dry-run commit 不变。
- 推送后以新的 Linux Clippy 和 workspace tests 作为 GREEN 门禁。

## 后继要求

- `bypass_tool_use_id` 的值必须仍为 `<tc.id>-bypass`。
- 后续对 `tc.id` 的引用必须继续编译，证明没有所有权语义变化。
- PR body 必须说明第二个原子 commit 和新增验证命令。

## 验证建议

- `cargo clippy --workspace --all-targets -- -D warnings`
- #1361 两条 exact 回归测试
- GitHub Actions `Test cosh-ng` 在 Rust 1.97 上完整通过 Clippy 和 workspace tests
